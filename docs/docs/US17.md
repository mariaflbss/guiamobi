# US17 — Notificações sobre alterações nas linhas

## História
Como usuário, quero receber notificações sobre alterações em linhas que utilizo e controlar minha inscrição nessas notificações.

## Requisitos relacionados
R30, R47, R69.

## Implementação
- O usuário ativa ou cancela as notificações push na tela **Notificações**.
- O usuário pesquisa uma linha por número ou nome e faz uma inscrição explícita.
- Cada inscrição é única por usuário e linha.
- O cancelamento pode ser feito individualmente por linha.
- O cancelamento das notificações push remove os dispositivos registrados, sem apagar as inscrições de linhas.
- A API consulta Service Alerts do GTFS-Realtime configurado.
- Alertas são direcionados apenas às linhas inscritas pelo usuário.
- A mesma ocorrência não é enviada duas vezes para a mesma inscrição.
- A rotina funciona independentemente da tela de navegação: a geração da notificação é feita pelo backend.
- Sem uma fonte GTFS-Realtime de Service Alerts configurada, nenhum alerta fictício é gerado.

## Critérios de aceitação
1. Alterações de trajeto, desvios e interrupções podem gerar notificações durante ou fora da navegação quando o feed oficial de Service Alerts estiver disponível.
2. O usuário consegue cancelar as notificações push do dispositivo.
3. O usuário consegue escolher linhas utilizadas com frequência e receber notificações direcionadas somente a essas linhas.

## Observação para teste
A entrega inclui a integração com `expo-notifications`. Para push remoto no Android, o Expo SDK 58 exige um development build; o Expo Go no Android não entrega push remoto a partir do SDK 53. A tela e o backend continuam sendo testáveis independentemente dessa limitação do Expo Go.
